# Move RawReliableAck server ACK-response generation into the acknowledger

## Goal

After this plan is complete, `IRawReliableAckServerAcknowledger.TryAck` returns both the accepted
session handler and the already-built ACK response, and `IRawReliableAckServerHandler` no longer
has `FillAckResponse`. The server endpoint sends the pre-built response after the low-level
connection is ready, before invoking handler `OnConnected`. All production code, tests, conformance
harness code, and normative documentation are updated to the new contract, and the repository builds
and tests cleanly.

## Context

RawReliableAck is a server-admission handshake:

1. The client fills ACK data and sends it.
2. The carrier reads the ACK request.
3. The server acknowledger validates the request and creates a session handler.
4. The server returns an ACK response to the client.
5. The server session becomes logically connected.

Before this change, the response is generated by the session handler through
`IRawReliableAckServerHandler.FillAckResponse` after the carrier has already buffered the ACK
request. The carrier passes the request into `RawReliableAckServerEndpoint`, which re-injects it as
an `AckRequestMessage` on connect, calls the handler to fill a transport-owned buffer, sends it, and
only then calls `OnConnected`.

The agreed target is:

- `TryAck` owns response construction and returns `(THandler handler, UnionDataList ackResponse)?`.
- The handler has no response-building callback.
- The carrier passes the response to the endpoint instead of the request.
- The endpoint no longer handles inbound `AckRequestMessage` at all; a duplicate request becomes a
  generic unsupported-frame protocol failure.

This is an in-process contract refactor. The wire frame types `AckRequestMessage` and
`AckResponseMessage` remain unchanged.

## Constraints

- Follow `AGENTS.md`: every project keeps its explicit `Nullable`, `LangVersion`, `ImplicitUsings`,
  and `TreatWarningsAsErrors` settings. Do not add new dependencies.
- Keep the requested method shape exactly:
  `(THandler handler, UnionDataList ackResponse)? TryAck(IEndPoint remote, UnionDataList ackData);`
- The acknowledger receives one additional reference to `ackData` and must release it exactly once,
  including on exceptional paths. This rule is unchanged.
- The returned `ackResponse` is owned by the transport after the call. The acknowledger must not
  release or retain it after returning.
- ACK responses must be acquired from a collectable pool (for example
  `Memory.CollectablePool.Acquire<UnionDataList>()`). `new UnionDataList()` has a zero ref count and
  is not a valid transferable resource.
- Do not change the wire protocol, frame-type values, `RawReliableAckInfo.AckMaxByteSize`, or the
  client-side handshake.
- Do not change unrelated behaviour, formatting, or dependencies.
- Test suites must follow `Tests/RULES.md`: each stage that adds, removes, renames, or moves tests
  must update the owning `Coverage.md` in that same stage.
- Do not modify the sibling `Pontifex copy` directory or any file outside this repository.
- Commit one stage at a time. Never commit a failed stage or unrelated files.
- Only the projects named in a stage's verification are expected to be green after that stage. A
  stage commit is valid when its own verification passes even though dependent production and test
  projects may still be red until their owning stages. Do not run `dotnet build Pontifex.sln` before
  Stage 13; a solution-wide failure before then is expected and is not a stage failure.

## Non-goals

- No protocol versioning, authentication, compression, or reconnection policy changes.
- No conformance-control implementation rewrite. The existing RawReliableAck conformance suite is
  updated to the new contract but remains `[Ignore]`d; no runtime conformance claim is made.
- The only public API changes allowed are the requested acknowledger result, removal of
  `IRawReliableAckServerHandler.FillAckResponse` and `IHandlerWrapper.FillAckResponse`, the
  `ServerSideApiFactory<TApi>` interface and `TryAck` adaptation required by invariant `THandler`,
  the optional `ServerSideApiFactory` memory parameter, and the protected renames of
  `RawReliableAckServerTransport.TryAcknowledge`,
  `RawReliableAckServer.TryConnectNewClient`, and
  `RawReliableAckServerEndpoint.SetPendingAckData`/`ReleasePendingAckData`.
- No change to `FillAckData`, the client `OnConnected(..., ackResponse)` signature, or the client
  endpoint.
- No opportunistic cleanup of unrelated classes.

## Assumptions

- The user explicitly chose to remove the endpoint's inbound ACK-request handling entirely.
- C# variance rules reject `out THandler` when `THandler` is used inside a value tuple, so `out` is
  removed and `ServerSideApiFactory<TApi>` is changed to implement the invariant
  `IRawReliableAckServerAcknowledger<IRawReliableAckServerHandler>`.
- `ServerSideApiFactory` may receive an optional `IMemoryRental`; when omitted it uses
  `MemoryRental.Shared`, preserving source compatibility for existing callers.
- On a reconnectable reattach there is no session handler response callback anymore, so the
  reconnectable layer reuses the ACK response composed for the original session.
- `dotnet build` and `dotnet test` work in this environment when NuGet audit is disabled with
  `-p:NuGetAudit=false`. Without that property, an unreachable `api.nuget.org` produces `NU1900`,
  which `TreatWarningsAsErrors=true` promotes to an error in the `netstandard2.1` projects.
- The Direct RawReliableAck conformance test fixture remains `[Ignore]`d; its compilation must still
  succeed.
- No reconnectable handshake test suite exists in the repository. Stage 4 is therefore verified at
  compile level, and its runtime behaviour is reviewed rather than automatically tested.

### Objective

Compose reconnectable ACK responses in the acknowledger path, store them for reattachment, and
remove `ReconnectableServerLogic.FillAckResponse`.

### Inputs

- Stage 1 complete (including `RawReliableAckServer.TryConnectNewClient` returning the tuple).
- `Protocols/Pontifex.Protocol.Reconnectable/Raw/Reliable/Ack/RawReliableAckReconnectableServer.cs`.
- `Protocols/Pontifex.Protocol.Reconnectable/Raw/Reliable/Ack/ReconnectableServerLogic.cs`.
- Stage 3 is not a compile dependency: `Pontifex.Protocol.Reconnectable.csproj` references only
  `Pontifex.csproj`.

### Actions

1. `ReconnectableServerLogic.cs`:
   - Add a `private UnionDataList? _ackResponse;` field and a
     `private readonly object _ackResponseLock = new();` field.
   - Delete `IRawReliableAckServerHandler.FillAckResponse`.
   - Add:
     ```csharp
     public UnionDataList CreateAckResponse(UnionDataList userAckResponse)
     public UnionDataList? CloneAckResponse()
     public void ReleaseAckResponse()
     ```
   - `CreateAckResponse` must:
     1. Acquire an empty `UnionDataList` from `Memory.CollectablePool`.
     2. `CopyFrom(userAckResponse)` (the target is still empty).
     3. Prepend, in this order using `PutFirst`: `new UnionData(_secret)`,
        `new UnionData(_sessionId.Generation)`, `new UnionData(_sessionId.Id)`, and
        `new UnionData(ReconnectableInfo.AckOKResponse)`.
     4. Store `response.Clone(Memory.CollectablePool)` in `_ackResponse`.
     5. Return the composed `response` and release `userAckResponse` in a `finally` block.
     6. If any step after the acquire throws, release the partially composed `response` in a
        `catch` block before rethrowing. Do not leave `_ackResponse` pointing at a partial response.
   - `CloneAckResponse` takes `_ackResponseLock`, clones the stored response while holding the lock,
     and returns the clone.
   - `ReleaseAckResponse` takes `_ackResponseLock`, exchanges the field to null, releases the stored
     response, and returns. The lock makes cloning and release mutually exclusive because the
     driver thread may release while the carrier thread reattaches.
   - `CreateAckResponse` stores `_ackResponse` under `_ackResponseLock`.
   - Ensure `using System.Threading;` is present if `Interlocked` is still used elsewhere.
2. `RawReliableAckReconnectableServer.cs`:
   - Change `TryAck` to return
     `(IRawReliableAckServerHandler handler, UnionDataList ackResponse)?`.
   - Reattach path, in this order:
     1. Call `logic.CloneAckResponse()` before `Reattach`. If it is null, return null without
        changing `mAttached`.
     2. Call `logic.Reattach(secret.Acquire())`. If it fails, release the cloned response and return
        null.
     3. Return `(logic, clonedResponse)`.
   - New-session path, in this exact order:
     1. Call `TryConnectNewClient(remote, ackData.Acquire())` and require a tuple. Construct
        `ReconnectableServerLogic` with the returned handler. Preserve the existing
        `logic.OnConnected += ...` and `logic.OnStopped += ...` subscriptions before adding the
        session; the stop subscription must also call `logic.ReleaseAckResponse()`.
     2. Call `_sessionsMap.AddSession(logic)`. If the id is invalid, release the user ACK response,
        notify the user handler once with
        `OnStopped(new TextFail(ReconnectableInfo.TransportName, "Session map is full"))`, and return
        null.
     3. Call `logic.Attach(sessionId)`.
     4. Call `logic.CreateAckResponse(userAckResponse)` inside a `try`/`catch`. On failure, remove the
        session, call `logic.ReleaseAckResponse()`, notify the user handler once with
        `OnStopped(new TextFail(ReconnectableInfo.TransportName, "Failed to compose the ACK response"))`,
        and rethrow so the transport logs the exception. The logic driver must not have been started
        yet.
     5. Start `_sessionsLogicDriver` only after the composed response exists. If start fails, remove
        the session, call `logic.ReleaseAckResponse()`, release the composed response, notify the
        user handler once with
        `OnStopped(new TextFail(ReconnectableInfo.TransportName, "Failed to start the session logic"))`,
        and return null.
     6. Return `(logic, composedAckResponse)`.
   - In the `logic.OnStopped` event handler, after removing the session, call
     `logic.ReleaseAckResponse()`.
   - Update XML/comments that mention `FillAckResponse`.

### Risks / notes

- `CreateAckResponse` takes ownership of the user response. Do not release it twice.
- Every `TryAck` failure after `TryConnectNewClient` succeeded must notify the user handler exactly
