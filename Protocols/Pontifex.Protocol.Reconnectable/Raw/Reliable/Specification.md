# Reconnectable Specification

## 1. Scope

`reconnectable` is a wrapper that implements
[`RawReliable`](../../../../Pontifex/Abstractions/Transports/Raw/Reliable/Specification.md)
over exactly one nested `RawReliable` transport and keeps one logical session
alive across a loss of the underlying connection.

This implementation adds session identity, a server-held session secret, shared
delivery state across reconnects, and its own negotiation exchange. It does not
change the delivery guarantee, the send results, or the buffer ownership of the
abstract type.

### 1.1 References

- [`RawReliable`](../../../../Pontifex/Abstractions/Transports/Raw/Reliable/Specification.md)
  — the contract implemented here.

## 2. Normative language

The key words **MUST**, **MUST NOT**, **REQUIRED**, **SHOULD**, **SHOULD NOT**,
and **MAY** in this document are to be interpreted as described in
[RFC 2119](https://datatracker.ietf.org/doc/html/rfc2119).

## 3. Contract

The wrapper is selected by the scheme `reconnectable` and produces an
`IRawReliableClient` or an `IRawReliableServer` of the abstract type. It is
registered for `TransportType.RawReliable` and is obtained through a required
nested `RawReliable` transport.

## 4. Scheme and negotiation

- Scheme: `reconnectable`
- Negotiation name: `reconnectable`
- Negotiation version: `1`
- Custom tail: session id, generation, and secret

After the inner transport reports `OnConnected`, the wrapper performs its own
negotiation in a flat `UnionDataList` envelope:

```text
Request:  [version, name, NegotiationStatus.Request,  ...custom tail]
Response: [version, name, NegotiationStatus.Accepted, ...custom tail]
Reject:   [serverVersion, serverName, NegotiationStatus.Rejected, text?]
```

The status element is always the discriminator. The wrapper enforces its own
handshake limit and handshake deadline, and it waits before disconnecting the
inner transport after a reject.

A reconnect reuses the session id and generation with a fresh secret check. The
server keeps the negotiation response so that a returning client can reattach to
the same session.

## 5. Parameters

| Parameter | Type and unit | Required | Default | Meaning |
| --- | --- | --- | --- | --- |
| `disconnect_timeout` | integer, seconds | yes | none | How long the server keeps a detached session before terminating it. |
| `nested` | transport, `RawReliable` | yes | none | The transport wrapped by `reconnectable`. |
| `handshake_max_byte_size` | integer, bytes | no | `128` | Inbound handshake limit of the wrapper. |

Every parameter is implementation configuration, not part of the abstract
contract.

## 6. Lifecycle and teardown

The wrapper owns one logical session, its delivery state, and the server-held
secret. The session is shared by every underlying connection.

When the inner connection drops, the session **MUST NOT** terminate immediately.
The server keeps it for `disconnect_timeout` and accepts a reattach that presents
the matching session id, generation, and secret. The client retries the nested
connection periodically while the session is detached.

When `disconnect_timeout` expires before a successful reattach, the session
terminates with the abstract terminal sequence. Stop terminates every session and
stops the nested transport.

The server limits the number of concurrently tracked sessions and rejects a new
session beyond that limit. This limit is implementation configuration.

## 7. Failure, deviations, and protection

A nested connection failure detaches the session rather than failing it. A
negotiation reject or timeout terminates the session. An unrecoverable failure of
the nested transport is reported as the wrapper's failure.

This implementation declares no deviation from the abstract type. The secret
authenticates reattachment to the session; it does not authenticate the peer and
adds no confidentiality.

## 8. Implementation-defined choices

| Area | Choice |
| --- | --- |
| Secret form | Generated by the server; carried in the negotiation tail. |
| Reconnect period | Retry every 2 seconds while detached. |
| Session limit | 20000 tracked server sessions. |
| Reattach acceptance | Server-side validation of session id, generation, and secret. |
| Delivery state | Shared across underlying connections for the session lifetime. |

## 9. Implementer checklist

- [ ] Register the scheme `reconnectable` for `TransportType.RawReliable`.
- [ ] Require exactly one nested `RawReliable` transport.
- [ ] Negotiate with name `reconnectable` and version `1`.
- [ ] Carry session id, generation, and secret in the custom tail.
- [ ] Use the status element as the discriminator.
- [ ] Keep the session alive for `disconnect_timeout` after a nested loss.
- [ ] Accept a reattach only when id, generation, and secret match.
- [ ] Share delivery state across every connection of one session.
- [ ] Terminate the session when `disconnect_timeout` expires.
- [ ] Enforce the configured server session limit.
- [ ] Enforce `handshake_max_byte_size` on the inbound handshake.
- [ ] Provide no confidentiality claim for the secret.
